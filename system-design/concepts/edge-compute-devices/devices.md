# Target Compute

Target Compute is the compute surface that Margo workloads are deployed to and run on. It is defined by the capabilities it provides to the Margo ecosystem. When a client onboards with a workload fleet manager, it reports what its Target Compute can do, and the fleet manager uses that information to decide which workloads that Target Compute can host. Reported capabilities fall into the following categories.

Target Compute is a logical surface rather than a physical one. It is provided by an edge compute device, either directly or through a gateway service, which keeps the deployment model the same whether the underlying hardware hosts a Margo client itself or is represented by something that does.

## Target Name

Each Target Compute surface carries a Target Name: the human assigned name operators use to recognize it and select it when deploying workloads. The name is chosen by people rather than generated by the system, so it should be treated as a label rather than an identifier. It conveys no trust or authorization, and it is not the identity a client authenticates with. Component identity comes from the [Margo Identity and Authorization Framework](../identity/identity-and-trust.md).

## Supported Deployment Types

This describes the type of workload manifests the Target Compute can interpret and apply to its local workload runtime. Common examples are Helm and Compose manifests. A Target Compute surface may support more than one deployment type, giving the fleet manager flexibility in how workloads are packaged and delivered.

## Supported Runtimes

This describes the workload runtime available to execute deployed workloads. Margo currently supports the OCI runtime. Additional runtimes may be added in the future. As with deployment types, a Target Compute surface may report more than one runtime.

## Compute Resources

To ensure a Target Compute surface can host the workloads assigned to it, it reports the compute resources it makes available to Margo, including CPU, memory, and storage, along with peripherals and network interfaces. These resources are reported during the final stage of onboarding and updated whenever a change occurs, so the fleet manager can always match workload requirements against real, available capacity.

## Edge Compute Devices

An edge compute device is the physical or virtual infrastructure that provides Target Compute. It supplies the hardware, operating system, container orchestration platform, and peripherals that workloads ultimately consume. Device vendors, device identity, and device lifecycle management all operate at this layer. For more on the device layers themselves, see the [edge compute device overview](../../overview/edge-compute-devices.md).

## Gateway Services

Gateway services add flexibility at the edge compute layer by connecting devices that do not host a Margo management client of their own. A gateway service can act as an **opaque gateway**, which combines the capabilities of several child devices and presents them to the fleet manager as a single Target Compute surface, or as a **see-thru gateway**, which reports each child device individually so the fleet manager sees a distinct Target Compute surface for each one. For the full description of gateway behavior, see [Gateways](../gateways/gateways.md).
